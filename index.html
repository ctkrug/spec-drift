An OpenAPI breaking-change detector that speaks plain English

Spec Drift is a browser-based OpenAPI breaking change detector. Paste an old and a new spec and it reads the difference through OpenAPI semantics, then tells you which changes will break a client integration and which are safe to ship. There is no JSON diff to decode, no account, and no server round-trip: the comparison runs entirely in your tab.

What counts as a breaking change in an OpenAPI spec?
A change that can make a previously valid client request fail, or make a response the client relied on disappear. Spec Drift flags a parameter or body field becoming required, a path or operation being removed, an enum value being dropped, a request type being narrowed, and a response field being removed or made optional. Additive changes (a new optional field, a widened enum, a new endpoint) are listed separately as safe.
How is this different from a Swagger diff tool?
A Swagger diff tool online shows you the textual delta between two files. Spec Drift is a checker, not a differ: instead of raw plus/minus lines it classifies each change by client impact and writes it as a sentence, like "user_id became required, so any client not sending it will now get a 400." You get the answer, not the homework.
Do I need to upload my spec anywhere?
No. Spec Drift is a client-side API breaking change checker. Your specs never leave the browser, there is no backend, and nothing is stored. The optional share link encodes the two specs into the URL itself, so even sharing a report involves no server.
Which OpenAPI versions does it support?
OpenAPI 3.0 and 3.1, in JSON or YAML. It treats 3.0's nullable: true and 3.1's type: [..., "null"] as equivalent, so migrating between the two dialects does not show up as a false breaking change.
Can I use the report in a pull request or release notes?
Yes. Export the report as Markdown and paste it into a PR description, a changelog, or release notes. Or copy a share link that reproduces the exact report for a teammate.
